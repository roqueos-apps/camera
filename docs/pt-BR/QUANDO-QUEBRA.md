# Quando quebra

_Português | [English](../WHEN-IT-BREAKS.md)_

> **Para quem:** quem vê algo falhar ao instalar, ao rodar o gate, ao usar o app ou ao publicar uma versão.
> **O que tem aqui:** o primeiro comando de diagnóstico, e então, por área, uma tabela com o que aparece, a causa e o que fazer, com a mensagem literal. Falha que já aconteceu leva a data.
> **Onde ir para o resto:** como as peças se ligam, [ARQUITETURA.md](ARQUITETURA.md); os comandos, [REFERENCIA.md](REFERENCIA.md); o que cada teste prova, [TESTES.md](TESTES.md).

As mensagens são citadas como o programa imprime, em português quando o programa escreve em português. Os textos da própria tela do app aparecem em inglês (`en-US`) e em português (`pt-BR`), os dois idiomas destes documentos; os outros oito idiomas dizem a mesma coisa.

## Primeiro, o diagnóstico

```bash
node -v && yarn -v
yarn verificar
yarn app:check
```

O `yarn verificar` para no primeiro passo que falha (lint, formato, testes, `app check`), então as últimas linhas dizem qual foi. No app, abra o console do navegador e procure `[useCamera]` e `[camera]`: toda falha que o código pega é registrada com um desses prefixos ([REFERENCIA.md](REFERENCIA.md#nomes-e-códigos-que-atravessam-fronteira)).

## Instalação

| O que aparece                                                                                                      | Causa                                                                                          | O que fazer                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Permission denied (publickey)` enquanto o Yarn busca o `@roqueos-apps/ui` (visto no GitHub Actions em 29/09/2026) | a dependência estava pinada por `git+ssh`, e a máquina não tem chave SSH para o GitHub         | pinar por HTTPS, `github:roqueos-apps/ui#v0.6.0`, como a `main` faz desde então ([CHANGELOG.md](../../CHANGELOG.md)); num branch antigo, rebase na `main` |
| O Yarn recusa com `The engine "node" is incompatible with this module`                                             | Node mais velho que o 22 (`engines` do `package.json`); o texto exato não foi reproduzido aqui | `nvm use` (o `.nvmrc` do repo é 24), e instale de novo                                                                                                    |
| `yarn install --frozen-lockfile` falha dizendo que o lockfile precisa ser atualizado                               | o `package.json` mudou sem o `yarn.lock`                                                       | `yarn install --ignore-scripts` e commit do `yarn.lock` junto com a mudança                                                                               |

Run Prettier with --write to fix.`                                                                                                                 | um arquivo fora do formato; Markdown conta, porque o `.prettierignore` não o exclui                                       | `yarn format`, revise o diff, faça commit                                               |
| `AssertionError: expected { faltam: [ 'torch' ], sobram: [] } to deeply equal { faltam: [], sobram: [] }` no `textos.spec.js` (reproduzido em 18/11/2026 apagando `torch` do `de-DE.json` numa cópia) | a tela pede uma chave que um idioma não tem (`faltam`), ou um idioma guarda uma chave que a tela não pede mais (`sobram`) | ponha a chave nos dez `i18n/*.json`, ou tire a sobra dos dez                            |
| `REPROVOU  textos nos idiomas` seguido de `i18n/de-DE.json sem: torch`                                                                                                                                | o `app check` vê um idioma sem uma chave que o `pt-BR` tem                                                                | o mesmo conserto; o `pt-BR` é o idioma canônico                                         |
| `REPROVOU` com `importa "...": o app não fala com banco, quem guarda é o sistema`, ou `que só existe dentro do RoqueOS`                                                                               | um import fora de `vue`, `@roqueos-apps/app-sdk`, `@roqueos-apps/ui` e dos arquivos deste repo                            | tire; o que o app precisa do RoqueOS vem pelo `sistema`                                 |
| `REPROVOU` com `usa ... que não está entre as variáveis do sistema que um app pode usar`                                                                                                              | uma variável `--ros-*` fora do contrato do SDK                                                                            | use uma variável do contrato, ou uma do app, `--camera-*`                               |
| `REPROVOU` com `usa sistema.<cap> sem "<cap>" em capacidades no app.json`, ou `sem "Imagens" em pastas no app.json`                                                                                   | uma capacidade ou pasta usada no código e não declarada                                                                   | declare no `app.json` e no `CAPACIDADES` do `src/index.js` (o teste compara)            |
| O teste "o id e as capacidades são os do manifesto, e o manifesto é válido" falha                                                                                                                     | o `app.json` e o `CAPACIDADES` do `src/index.js` discordam                                                                | mantenha as duas listas iguais; o `src/index.js` não pode importar o JSON (veja abaixo) |
| O check `dco` de um pull request imprime `::error::commit <sha> sem Signed-off-by. Refaça com: git commit --amend -s (ou git rebase --signoff)`                                                       | um commit sem `Signed-off-by`                                                                                             | `git rebase --signoff main` e `git push --force-with-lease` no seu branch               |

## O app rodando

| O que aparece                                                                                                                                                 | Causa                                                                                                                                                   | O que fazer                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "Camera access denied" / "Acesso à câmera negado", com "Allow camera access in browser settings" / "Permita o acesso à câmera nas configurações do navegador" | o `getUserMedia` recusou com `NotAllowedError` ou `PermissionDeniedError`                                                                               | libere a câmera para o site nas configurações do navegador; então Tentar novamente ("Retry" / "Tentar novamente") pede de novo                             |
| "Camera unavailable" / "Câmera indisponível" com "Error starting camera" / "Erro ao iniciar câmera"; o console mostra `[useCamera] start failed:`             | qualquer outra falha: a câmera está com outro programa, não há câmera, ou o navegador não tem `getUserMedia` (o motor lança `getUserMedia unsupported`) | feche o outro programa ou ligue uma câmera, e Tentar novamente. Antes da 0.1.0 esse caso deixava o visor preto e mudo ([CHANGELOG.md](../../CHANGELOG.md)) |
| Salvar mostra "Sign in to save to Files." / "Entre na sua conta para salvar em Arquivos."                                                                     | sem conta: o sistema recusa com `sem-conta`                                                                                                             | esperado. A captura fica na tela; Baixar e Compartilhar continuam. Entre na conta para salvar nos Arquivos                                                 |
| Salvar mostra "Error saving image" / "Erro ao salvar imagem"; o console mostra `[camera] salvar` com um código                                                | o sistema recusou por outro motivo                                                                                                                      | leia o código no console; os códigos são os do SDK (por exemplo `pasta-nao-declarada` se `Imagens` saiu de `pastas`)                                       |
| Sem botão de lanterna, ou sem botão de trocar a câmera                                                                                                        | a trilha não declara `torch`, ou o aparelho lista um `videoinput` só                                                                                    | esperado: os botões seguem o que o aparelho sustenta                                                                                                       |
| O nível não liga, no iOS                                                                                                                                      | o `DeviceOrientationEvent.requestPermission()` respondeu outra coisa que não `granted`                                                                  | libere o acesso a movimento e orientação para o site, e ligue o nível de novo                                                                              |
| O disparador embaixo da barra de gestos do iPhone (corrigido na 0.1.1, 28/09/2026)                                                                            | a margem de baixo usava só o `env(safe-area-inset-bottom)`, que zera quando uma folha trava o body                                                      | mantenha `var(--safe-area-inset-bottom, env(...))`; o `test/estilo.spec.js` reprova do contrário                                                           |
| "Iniciando câmera" dito duas vezes, no título e embaixo (corrigido na 0.1.3, 28/09/2026, achado no QA)                                                        | o título e o subtítulo do carregando usavam o texto                                                                                                     | o carregando tem só o título agora ([`src/Camera.vue`](../../src/Camera.vue))                                                                              |

## Publicação

| O que aparece                                                                                                               | Causa                                                                                                                | O que fazer                                                                                             |
| --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| O build do RoqueOS quebra num import de JSON (visto nos jogos em 25/09/2026)                                                | um `import x from '...json'` direto fora do `src/i18n/` do RoqueOS: o plugin do vue-i18n dele embrulha o `vite:json` | carregue o JSON como texto com `?raw` e `JSON.parse`, como o [`src/textos.js`](../../src/textos.js) faz |
| `paridade: #<n> (<funcionalidade>): test/<arquivo> não tem o teste "<título>"` no RoqueOS                                   | um teste citado no `paridade.json` foi renomeado ou tirado                                                           | atualize a citação no `paridade.json` no mesmo commit do teste                                          |
| `paridade: #<n> (<funcionalidade>): mudou sem "nota"`, ou `perdida sem "decisao" (quem decidiu, quando, onde está escrito)` | uma funcionalidade mudou ou se perdeu sem a nota ou a decisão escrita                                                | escreva a nota, ou a decisão com quem decidiu, quando e onde                                            |
| `paridade: o "files" do package.json não publica o paridade.json`                                                           | o `paridade.json` saiu do `files`                                                                                    | ponha de volta no `files`                                                                               |
