# When it breaks

_[Português](pt-BR/QUANDO-QUEBRA.md) | English_

> **For whom:** whoever sees something fail while installing, running the gate, using the app or publishing a version.
> **What is here:** the first diagnostic command, then, by area, a table of what shows up, the cause and what to do, with the literal message. Failures that already happened carry the date.
> **Where to go for the rest:** how the parts connect, [ARCHITECTURE.md](ARCHITECTURE.md); the commands, [REFERENCE.md](REFERENCE.md); what each test proves, [TESTING.md](TESTING.md).

Messages are quoted as the program prints them, in Portuguese when the program writes Portuguese. The app's own screen texts are quoted in English (`en-US`) and Portuguese (`pt-BR`), the two languages of these docs; the other eight languages say the same thing.

## First, the diagnosis

```bash
node -v && yarn -v
yarn verificar
yarn app:check
```

`yarn verificar` stops at the first step that fails (lint, format, tests, `app check`), so the last lines say which one. In the app, open the browser console and search for `[useCamera]` and `[camera]`: every failure the code catches is logged with one of these prefixes ([REFERENCE.md](REFERENCE.md#names-and-codes-that-cross-a-boundary)).

## Installing

| What shows up                                                                                                | Cause                                                                                       | What to do                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Permission denied (publickey)` while Yarn fetches `@roqueos-apps/ui` (seen on GitHub Actions on 29/09/2026) | the dependency was pinned over `git+ssh`, and the machine has no SSH key for GitHub         | pin over HTTPS, `github:roqueos-apps/ui#v0.6.0`, as `main` does since then ([CHANGELOG.md](../CHANGELOG.md)); on an old branch, rebase on `main` |
| Yarn refuses with `The engine "node" is incompatible with this module`                                       | Node older than 22 (`engines` in `package.json`); the exact wording was not reproduced here | `nvm use` (the repo's `.nvmrc` is 24), then install again                                                                                        |
| `yarn install --frozen-lockfile` fails saying the lockfile needs to be updated                               | `package.json` changed without `yarn.lock`                                                  | `yarn install --ignore-scripts` and commit `yarn.lock` with the change                                                                           |

## The gate

| What shows up                                                                                                                                                                                            | Cause                                                                                                                                  | What to do                                                                               |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `[warn] Code style issues found in the above file. Run Prettier with --write to fix.`                                                                                                                    | a file out of format; Markdown counts, since `.prettierignore` does not exclude it                                                     | `yarn format`, review the diff, commit                                                   |
| `AssertionError: expected { faltam: [ 'torch' ], sobram: [] } to deeply equal { faltam: [], sobram: [] }` in `textos.spec.js` (reproduced on 18/11/2026 by deleting `torch` from `de-DE.json` in a copy) | the screen asks for a key that a language does not have (`faltam`), or a language keeps a key the screen no longer asks for (`sobram`) | add the key to the ten `i18n/*.json`, or remove the leftover from all ten                |
| `REPROVOU  textos nos idiomas` followed by `i18n/de-DE.json sem: torch`                                                                                                                                  | `app check` sees a language missing a key that `pt-BR` has                                                                             | the same fix; `pt-BR` is the canonical language                                          |
| `REPROVOU` with `importa "...": o app não fala com banco, quem guarda é o sistema`, or `que só existe dentro do RoqueOS`                                                                                 | an import outside `vue`, `@roqueos-apps/app-sdk`, `@roqueos-apps/ui` and this repo's files                                             | remove it; what the app needs from RoqueOS comes through the `sistema`                   |
| `REPROVOU` with `usa ... que não está entre as variáveis do sistema que um app pode usar`                                                                                                                | a `--ros-*` variable outside the SDK contract                                                                                          | use a contract variable, or an app variable `--camera-*`                                 |
| `REPROVOU` with `usa sistema.<cap> sem "<cap>" em capacidades no app.json`, or `sem "Imagens" em pastas no app.json`                                                                                     | a capability or folder used in code and not declared                                                                                   | declare it in `app.json` and in `CAPACIDADES` of `src/index.js` (the test compares them) |
| The test "o id e as capacidades são os do manifesto, e o manifesto é válido" fails                                                                                                                       | `app.json` and `CAPACIDADES` in `src/index.js` disagree                                                                                | keep both lists equal; `src/index.js` cannot import the JSON (see below)                 |
| The `dco` check on a pull request prints `::error::commit <sha> sem Signed-off-by. Refaça com: git commit --amend -s (ou git rebase --signoff)`                                                          | a commit without `Signed-off-by`                                                                                                       | `git rebase --signoff main` and `git push --force-with-lease` on your branch             |

## The app at runtime

| What shows up                                                                                                                                                  | Cause                                                                                                                                                             | What to do                                                                                                                                             |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| "Camera access denied" / "Acesso à câmera negado", with "Allow camera access in browser settings" / "Permita o acesso à câmera nas configurações do navegador" | `getUserMedia` rejected with `NotAllowedError` or `PermissionDeniedError`                                                                                         | allow the camera for the site in the browser settings, then Retry ("Retry" / "Tentar novamente") asks again                                            |
| "Camera unavailable" / "Câmera indisponível" with "Error starting camera" / "Erro ao iniciar câmera"; the console shows `[useCamera] start failed:`            | any other failure: the camera is held by another program, there is no camera, or the browser has no `getUserMedia` (the engine throws `getUserMedia unsupported`) | close the other program or connect a camera, then Retry. Before 0.1.0 this case left the viewfinder black and silent ([CHANGELOG.md](../CHANGELOG.md)) |
| Save shows "Sign in to save to Files." / "Entre na sua conta para salvar em Arquivos."                                                                         | no account: the system refuses with `sem-conta`                                                                                                                   | expected. The capture stays on screen; Download and Share still work. Sign in to save to Files                                                         |
| Save shows "Error saving image" / "Erro ao salvar imagem"; the console shows `[camera] salvar` with a code                                                     | the system refused for another reason                                                                                                                             | read the code in the console; the codes are the SDK's (for example `pasta-nao-declarada` if `Imagens` left `pastas`)                                   |
| No torch button, or no switch-camera button                                                                                                                    | the track declares no `torch`, or the device lists only one `videoinput`                                                                                          | expected: the buttons follow what the device supports                                                                                                  |
| The level does not turn on, on iOS                                                                                                                             | `DeviceOrientationEvent.requestPermission()` answered something other than `granted`                                                                              | allow motion and orientation access for the site, then toggle the level again                                                                          |
| The shutter under the iPhone gesture bar (fixed in 0.1.1, 28/09/2026)                                                                                          | the bottom margin used `env(safe-area-inset-bottom)` alone, which zeroes when a sheet locks the body                                                              | keep `var(--safe-area-inset-bottom, env(...))`; `test/estilo.spec.js` fails otherwise                                                                  |
| "Starting camera" said twice, in the title and below it (fixed in 0.1.3, 28/09/2026, found in QA)                                                              | title and subtitle of the loading state both used the text                                                                                                        | the loading state has only the title now ([`src/Camera.vue`](../src/Camera.vue))                                                                       |

## Publishing

| What shows up                                                                                                        | Cause                                                                                                   | What to do                                                                                  |
| -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| RoqueOS's build breaks on a JSON import (seen in the games on 25/09/2026)                                            | a direct `import x from '...json'` outside RoqueOS's `src/i18n/`: its vue-i18n plugin wraps `vite:json` | load JSON as text with `?raw` and `JSON.parse`, as [`src/textos.js`](../src/textos.js) does |
| `paridade: #<n> (<feature>): test/<file> não tem o teste "<title>"` in RoqueOS                                       | a test cited in `paridade.json` was renamed or removed                                                  | update the citation in `paridade.json` in the same commit as the test                       |
| `paridade: #<n> (<feature>): mudou sem "nota"`, or `perdida sem "decisao" (quem decidiu, quando, onde está escrito)` | a feature changed or was lost without the written note or decision                                      | write the note, or the decision with who decided, when and where                            |
| `paridade: o "files" do package.json não publica o paridade.json`                                                    | `paridade.json` left `files`                                                                            | put it back in `files`                                                                      |
